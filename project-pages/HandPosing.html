Hand Posing Tool

This project was to redesign OneBonsai's existing hand-posing workflow. The old system technically worked, but it was cumbersome to use, produced inconsistent poses and required too much manual effort. My goal was to create a faster and more intuitive workflow that could be used across the company's VR projects.

The old workflow

The old workflow used inverse kinematics and a target position for each finger to hit. The issue with this is that it lacks controll for wrapping fringers around objects, which is most of what this system is used for.

Designing the Control Rig

My first prototype recreated the old workflow using inverse kinematics and target controls. Although it worked technically, the controls were too abstract and it was difficult to predict how moving them would affect the final hand. I discarded that version and designed a simpler rig around the controls people actually needed.

Each finger received a curl value and a restricted rotational control at its base joint. This made the rig easier to understand and reduced the chance of creating physically impossible poses.

Automatic Wrapping

To reduce repetitive work, I added a feature that automatically closes the hand around the selected object. This gives the user a useful starting pose instead of requiring every finger to be positioned manually. The result can then be refined with smaller adjustments.

Creating and Saving Grab Poses

The editor tool spawns the hand in the correct location, allows the user to define how an object should be held and stores the information needed at runtime. Each grabbable object can contain a pose animation, the relative transform between the hand and object and an interaction state such as holding, using or approaching.

The most technical part was saving the current skeletal pose. I wrote a C++ function that reads the transform of every hand bone and writes those transforms into a single-frame animation sequence. The tool also stores the relative object transform so the object can snap into the correct position when grabbed in VR.

Production Integration

I used Unreal Engine's Class Default Object system to write the generated pose and transform data back onto the selected object. This also had to work when the grab component was inherited from a parent Blueprint rather than placed directly on the object.

I later moved the system into the company's main branch, fixed mirrored-hand and inheritance issues, improved how poses were replaced or removed and migrated the runtime grab logic out of a large hand Blueprint into a reusable component. I also wrote internal documentation and a public development blog explaining the process.
